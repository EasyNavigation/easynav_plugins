std::size_t findClosestPoseIndex ( const nav_msgs::msg::Path & path,
const geometry_msgs::msg::Point & robot_position )
static

Index of the path pose closest to robot_position.

Since EasyNav controllers receive the full, un-pruned global path (see the README), the search for the carrot pose must start from this index instead of from the beginning of the path: otherwise, once the robot has advanced more than a lookahead distance away from the path's start pose, that start pose itself would (incorrectly) be picked up as "farther than the lookahead distance" and returned as the carrot, even though it lies behind the robot.

◆ getLookAheadPoint()

geometry_msgs::msg::Point getLookAheadPoint ( const nav_msgs::msg::Path & path,
const geometry_msgs::msg::Point & robot_position,
double lookahead_dist,
bool interpolate_after_end = false )
static

Finds the pose on the path at (approximately) lookahead_dist from robot_position.

Walks the path (in the same global frame as the robot pose), starting from the pose closest to the robot (see findClosestPoseIndex), looking for the first pose from there onwards that is farther than lookahead_dist from the robot, then interpolates the exact carrot position on the segment leading to it via a circle/segment intersection. If the remainder of the path is closer than lookahead_dist, the path's last pose is returned (extrapolated one extra segment if interpolate_after_end is true and the path has at least two poses).

◆ shouldRotateToPath()

bool shouldRotateToPath ( double angle_to_path,
bool currently_rotating ) const

Whether the robot should rotate in place towards angle_to_path.

Parameters
angle_to_pathCurrent angle (rad) from the robot's heading to the path.
currently_rotatingWhether the previous tick was already rotating in place. Hysteretic on currently_rotating: entering rotate-in-place mode requires angle_to_path to exceed rotate_to_heading_min_angle_, but once in it, leaving requires dropping to half that value (well-aligned, not merely back under the entry threshold) – otherwise a noisy angle hovering near the boundary (as it reliably does at a sharp turn, where the lookahead carrot itself is geometrically unstable tick to tick) chatters the controller between rotate-in-place and curve-follow mode every tick.
